# Text-to-LoRA-lite: deterministic prompt-conditioned factors

We ask whether a prompt representation can generate a request-specific low-rank adapter without an optimizer. Let h be the final prompt row from layer 0. For rank 2 on layer 1's q_proj (square width d), define A[0,:]=tanh(h), A[1,:]=tanh(2h), B[:,0]=h/d, B[:,1]=-h/d. Apply the additive overlay B A at scale 1 on subsequent forwards; keep the old KV. This deterministic hypernetwork isolates state authoring from model training. No replay, optimizer or host actions. Each request is independent and its factors are generated once after completed prefill, available on the next decode (publish lag 0).

Deliver `Workload()` with RequestState `factors` fields a/b and a low_rank Adapter consumer of q_proj at layer 1. Its tuple-valued @pllm.write method `produce(h,a,b)` writes the actual target-expanded field names (see docs); a/b arguments bind those fields and are only shape templates. h [rows,d], a [rows,2,d], b [rows,d,2]. Compute without in-place edits of inputs. Acceptance compares both factors, row isolation, state producer/consumer, timing, and B@A. All model dimensions come from model facts.
