# Reward learning in a TTRL host loop

We study test-time reward learning from completion groups. For each prompt independently, choose the most frequent nonempty normalized answer (strip and lowercase); ties go to the first encountered answer. Reward a valid answer 1 iff it equals the winner, otherwise 0. Empty answers have reward 0 and training weight 0; all valid answers have weight 1. Train a shared linear head w (initial zeros) on weighted MSE: sum_i weight_i*(h_i dot w-reward_i)^2 / max(sum weights,1), one framework AdamW step at lr 0.01, betas=(0.9,0.999), eps=1e-8, no decay per completion batch. Empty selections must leave state unchanged. The host handles voting between generate calls; no GPU tensor .item() is needed in workload math. No replay or external actions.

Deliver `Workload()` with InstanceState `head`, field w [width], and @pllm.train method `loss(hidden,targets,weights,w)` bound to WeightedRowBatch fields. Return pllm.UpdateOutput with changed/update_count=(weights.sum()>0), trained_rows=count(weights>0), and the scalar loss. Also deliver `vote(answers: list[str], groups: list[int]) -> tuple[list[float],list[float]]` and `feedback(head, hidden, answers, groups)` that calls vote, builds pllm.host.WeightedRowBatch and calls `head.train` exactly once, returning its result. The caller owns make_host/close and retries; feedback does not recreate the head. Acceptance checks grouped ties/missing labels, loss/gradients, repeated real CPU host steps, empty selection, and state release.
